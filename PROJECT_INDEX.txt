🎯 KEY INSIGHTS FROM SESSION
═════════════════════════════

1. Architecture > Optimization
   - Switching from LLM-first to memory-first was critical
   - Local lookups (instant, free) vs LLM calls (expensive, slow)
   - Proper architecture design beats prompt tweaking

2. Token Budgets Are Tight
   - Gemini 2.5-flash: ~1000 token budget (strict!)
   - Every character in prompt matters
   - Early detection + fallback essential

3. Personality Without Context
   - Off-topic queries don't need rich context
   - Light fallback (+ last exchange) is sufficient
   - Avoids wasting tokens on irrelevant augmentation

4. Fuzzy Search Wins
   - Exact keyword matching too strict
   - Prefix + word-level scoring handles natural language
   - Simple heuristics surprisingly effective

🎓 LESSONS FOR FUTURE IMPROVEMENTS
═══════════════════════════════════

1. Semantic Search
   - Replace keyword matching with embeddings
   - Better handling of synonyms & concepts
   - Higher compute cost but smarter results

2. Multi-Turn Context
   - Use last N messages, not just 1
   - Build conversation memory
   - Balance token usage vs context richness

3. Token Accounting
   - Monitor actual token usage
   - Alert on budget threshold
   - Dashboard for usage trends

4. Caching
   - LRU cache for identical queries
   - Time-based expiration
   - Further reduce LLM calls

5. Fine-tuning
   - Train model on domain-specific data
   - Better personality consistency
   - Reduced token usage per query
